# game — 마이크로게이트 실패-수정형 게임 광고 자극

`memorial0/game_setup`(내부 이름 `micro-rescue-experiment`)을 이 저장소로 흡수한 것이다.
가져온 시점의 원본 커밋: `11e85a98ae157d7dd52fb1687f0d25cbd3715669` ("package-lock.json 갱신").
이후 변경은 전부 이 저장소에서 관리하며, 원본 저장소로 되돌려 보내지 않는다.
파일·컴포넌트 이름의 "마이크로게이트"는 처음 만들 때 붙인 내부 이름이고, 화면에는 안 나온다.

## 화면에 보이는 것 — 심해

광고하는 앱은 가상의 심해 잠항 게임 **딥드리프트**다. 잠수정이 소나 빔을 쏘며 내려가고,
물고기 떼가 헤엄쳐 올라온다. 떼가 갈라져 생긴 **두 갈래 물길** 중 하나를 고른다 — 맑은 쪽은
출력이 오르고 물고기가 들어찬 쪽은 깎인다. 출력이 모자란 채 큰 떼를 만나면 실패한다.
큰 떼 앞에는 붉은 눈의 포식자가 몇 마리 앞장서고, 못 이길 떼가 다가오면 빔이 붉어진다.

**물길에는 아무것도 안 그린다.** 한때 물길과 적을 둥근 사각형으로 그리고 그 안에 물고기를
넣었고, 그다음엔 테두리를 지우고 물빛 띠만 남겼다. 둘 다 "박스가 내려온다"로 읽혔다.
지금은 **손해 쪽만 떼가 메우고 이득 쪽은 빈 물**이다 — 게이트 하나에는 늘 이득 하나와 손해
하나가 있으므로(두 타임라인 전부), 화면은 "떼가 반쪽을 막고 내려온다 → 빈 쪽으로 피한다"가
된다. 적의 몸도 무리 그 자체이고, 뒤에 가장자리로 사라지는 그림자만 깐다.

**판정 구간(`GATE_H` 40px)은 그대로다.** 떼가 그 구간을 정확히 채우므로 보이는 자리와 맞는
자리가 같다. 이득 쪽에 그림이 없어도 판정은 안 흐려진다 — 참가자가 하는 일은 좌우를 고르는
것뿐이고 세로 위치는 조작에 안 들어간다.

**흐름은 끊기지 않게 만든다.** 떼를 판정 구간에 딱 맞춰 그리면 사각형이 하나씩 내려오는
화면이 된다. 그래서 `drawSwarm(..., soft)` 로 **위아래 가장자리를 흐리게** 하고 구간 밖으로
넘겨 그린다 — 가운데 60% 는 그대로 진하므로 **진한 부분이 곧 판정 구간**이라는 관계는 남는다.
좌우는 안 흐린다(어느 쪽이 손해인지가 흐려지면 안 된다). 벽은 판정에 안 쓰이므로 훨씬 길게
뺀다(`WALL_OVER`).

**빔은 배경 떼만 가른다.** 잠수정이 알아서 쏘는 빔 근처의 배경 물고기가 옆으로 밀려난다 —
"쏘고 있다"가 눈에 보이게 하는 연출이다. **판정용 무리(보라)는 절대 밀지 말 것.** 밀면
"쏴서 없앴다"로 읽혀 실패의 원인이 선택이 아니라 조작 능력으로 옮겨 가고, 이 자극의 전제가
무너진다(위 "빔은 잠수정이 알아서 쏜다" 참고).

숫자(`+8` · `HP 24`)는 판 없이 글자만 띄운다(`drawLabel`). 판을 깔면 상자를 다 지운 화면에서
그것만 남아 도로 박스가 된다. **숫자 자체는 지우지 말 것** — 어느 쪽이 손해인지는 떼로 보이지만
얼마나 손해인지는 숫자로만 알 수 있고, 그건 자극의 정보량이다.

**화면을 채우는 것은 배경 떼(`state.school`)다.** 게이트의 벽은 폭이 20px 밖에 안 되는 얇은
띠라, 거기에만 물고기를 두면 화면에 물고기가 거의 안 보인다. 그래서 판정과 무관한 떼를 화면
전체에 띄워 크기별로 다른 속도로 흘려보낸다(원근). **색이 다르다** — 배경 떼는 푸른색
(`SEA.school`), 판정에 쓰이는 무리는 보라(`SEA.swarm`)다. 같은 색이면 "저 떼가 손해인가"를
매번 판단해야 해서 색 신호가 흐려진다. **배경 떼를 늘리거나 색을 바꿀 때 이 구분을 깨지 말 것.**
배치는 `rnd(seed)` 로 고정한다 — 참가자마다 다른 화면이 나오면 안 된다.

**빔은 잠수정이 알아서 쏘고, 겨냥은 참가자가 한다.** 발사 버튼은 없다 — 조작은 좌우 이동
하나 그대로다. 안전한 물길의 반대쪽에서 **기뢰**가 내려오고, 잠수정 앞으로 옮겨 맞히지 못하면
파워가 `MINE_COST` 만큼 깎인다. 난이도는 손이 느려서가 아니라 **게이트를 고르는 동시에
겨냥해야 해서** 올라간다.

이건 원래 전제("실패는 선택 때문이지 조작 능력 때문이 아니다")를 바꾼 것이고, 감수하고
넣은 것이다 — 무엇이 깨지는지는 INTEGRATION.md §10 에 적어 두었다. **되돌리려면 두
타임라인의 `mine(...)` 줄을 지우면 된다**(나머지 코드는 기뢰가 없으면 아무 일도 안 한다).

시청 조건에서는 자동 조종이 **위치와 무관하게 늘 요격에 성공한다.** 광고 속 자동 조종의
실패는 '선택' 때문이어야지 '겨냥을 놓쳐서'가 아니다 — 그래서 시청 조건의 수치는 기뢰를
넣기 전과 한 값도 안 달라진다.

원래는 삼각형 우주선이 숫자 상자 사이를 지나는 화면이었다. 세탁 광고는 사람이 나오는
이야기인데 게임 쪽이 계산 화면이면, 광고 태도 점수 차이가 **형식**(실패-수정형) 때문인지
**완성도** 때문인지 갈리지 않는다. 벌레가 아니라 물속 무리로 잡은 것은 혐오·밀집공포의
개인차가 광고 태도에 직접 얹히기 때문이다.

**바뀐 것은 그림뿐이다.** 타임라인·파워 계산·판정·노출 시간(31.2초/55.4초)·난이도·A/B
평행성은 그대로다. 세계관을 또 바꾸려면 `SEA` 팔레트와 `renderGame`·`drawSwarm`·
`drawFish`·`drawPredator`, 그리고 `APP`(제품 카드)만 손대면 된다 — 그 아래로는 내려가지 않는다.
단, 게이트 그림의 높이는 판정 상자(40)와 반드시 같아야 한다(`GATE_H`).

## 되감기는 참가자가 시작한다

실패 뒤 되감기가 저절로 일어나지 않는다. `rewind_watch` 단계에서 화면이 멈춘 채 [되돌리기]
버튼이 뜨고, 누르면 그때 `rewind_back` 으로 넘어간다. 누르기까지 걸린 시간은 `T_REWIND` 에
남는다. **세탁 자극의 장면 5 에도 같은 버튼이 있다** — 한쪽만 참가자가 누르게 하면 "이 광고에서
내가 주도했는가"가 자극마다 달라진다(INTEGRATION.md §11).

테스트 드라이버는 이 버튼을 눌러 줘야 한다(`harness.cjs` 의 `clickRewind`). 안 누르면
`rewind_watch` 에서 영원히 기다리는데, 그건 실제 참가자가 가만히 있을 때와 같은 상태다.

## 실행

```bash
npm install
npm run dev        # vite dev 서버 (기본 4173, 점유 시 자동 증가)
npm run build      # dist/ 로 정적 빌드 — 통합 러너가 iframe으로 읽는 산출물
npm test           # 세 조건을 jsdom 에서 끝까지 재생해 단계·로그·길이 확인 (약 1분 40초)
npm run difficulty # 개입 구간 성공률을 조작 정책별로 측정 (약 1분)
npm run parallel   # ver A·B 가 "소재만 다른 같은 자극"인지 타임라인끼리 비교 (수 초)
```

앞의 두 개는 `ver=B` 를 붙이면 B 로 잰다 — `npm test ver=B`, `npm run difficulty ver=B`.
재생해서 재는 것이라 느리다. `npm run parallel` 은 재생하지 않고 타임라인 데이터를 직접
비교하므로 빠르고, 타임라인 값을 잘못 고쳤을 때 여기서 먼저 걸린다.

## 길이·난이도를 고치는 자리

- 길이: `RESCUE_SEC`·`TUTORIAL_SEC`·`REWIND_SEC` 상수와 `MAIN_TIMELINE_A`·`MAIN_TIMELINE_B` 의 `t`(초).
  고친 뒤 `npm test` 로 실측한다. 목표는 세탁 자극과 같은 watch 31초 / intervene 55초이고,
  **8초짜리 제품 카드가 그 안에 포함된다**(세탁의 장면 10 에 대응).
- **타임라인 앞쪽을 잘라 길이를 줄일 때는 `START_POWER` 를 함께 올려야 한다.** 잘라낸 구간의
  파워 순증만큼 올리면 그 뒤 전개가 그대로 유지된다. 이때 **좁은 적은 배가 다음 게이트를 향해
  움직이느라 비껴갈 수 있으니** 표만 보고 HP 를 빼지 말고 `npm test` 의 `POWER_END` 로 확인할 것 —
  실제로 여기서 5 를 잘못 세어 실패가 18.2초가 아니라 10.4초에 일어난 적이 있다.
- 난이도: 게이트의 이득/손해 값과 적 HP. 고친 뒤 `npm run difficulty` 로 확인한다.
- **A·B 는 한쪽만 고치면 안 된다.** 시각·값·HP·자동 조종의 오판 지점은 두 타임라인이 같아야
  평행 자극이 된다. 고친 뒤 `npm run parallel` 로 어긋난 데가 없는지 본다.
  **손해 상자는 반드시 음수여야 한다** — 둘 다 양수면 아무 데나 지나도 파워가 올라
  "개입이 결과를 바꾼다"는 조작 자체가 성립하지 않는다(실제로 그랬고, 무조작 성공률이 100%였다).
- 되감기 지점(`REWIND_SEC`)은 자동 조종의 첫 오판보다 **앞**이어야 한다. 이미 손해를 본
  지점에서 시작하면 참가자가 만회할 수 없어 성공률이 0%가 된다.

## 걷어낸 것 (통합 러너가 대신한다)

이 자극은 원래 **독립 실험 러너**였다. 통합 러너(`session.html`)가 참가자 ID·순서 배정·설문·
로그 내보내기를 전부 담당하므로 아래를 제거했다.

- 참가자 ID 입력 화면 / 공통 안내 / 세션 인트로 / 최종 비교 설문 / 완료 화면
- 세션별 설문 5문항 — 통합 설문(`survey.js`)으로 대체
- CSV/JSON 내보내기 버튼
- 2세션 루프(`CONDITION_ORDER`) — 이제 한 번에 조건 하나만 재생한다
- 시작 버튼 — 세탁 광고처럼 로드 즉시 재생한다

효과음은 한때 걷어냈다가(세탁 광고가 무음이라 자극 간 변량이었다) **두 자극 모두에 다시 넣었다.**
지금은 `src/sfx.js` 가 Web Audio 로 합성하고, 신호의 길이·세기·CTA 클릭음은 세탁 자극의
`laundry-ad/sfx.js` 와 **글자 그대로 같은 코어**에서 나온다(자극마다 다른 것은 음색뿐).
`laundry-ad: npm test sfx` 가 두 파일을 직접 비교한다. `?sound=0` 으로 끌 수 있다.

**배경음은 자극마다 다르다.** 여기는 가단조 루프(`BED_VOICE`) — 베이스·아르페지오·선율이
Am → F → C → G 를 100bpm 으로 9.6초마다 반복한다. 세탁은 가만히 깔린 장조 패드다.

곡을 고칠 때는 `BED_VOICE` 의 `seq`(반음 배열)와 `step`(한 칸 길이)만 만지면 된다. 재생 절차는
코어(`seqNote` · `BED.lookahead`)에 있고 두 자극 공용이라 여기서 안 건드린다. **한 바퀴 길이를
바꿀 때는 자극 길이(31.2초·55.4초)나 게이트 간격(약 2.6초)의 배수가 되지 않게 할 것** — 맞물리면
곡의 마디가 다음 사건을 예고해서, 참가자가 화면을 안 봐도 실패가 오는 걸 알게 된다.
음량 천장·페이드·켜고 끄는 절차는 코어의 `BED` 가 정하므로 한쪽만 크게 깔 수 없다.
세계관을 바꿀 때 소리도 같이 바꾸고 싶으면 `BED_VOICE` 만 고친다 — 그 아래(코어)는 두 자극 공용이라
한쪽만 고치면 `npm test sfx` 가 잡는다. 자극별 배경음의 대가는 INTEGRATION.md §3 참고.

남은 것: 게임 자극 자체(캔버스·타임라인·되감기·개입), 조건 파라미터, 종료 시 로그 postMessage.

## 알려진 미해결 사항

- **B 의 구출 난이도가 A 와 미세하게 다를 수 있다.** 최근 3회 측정은 60% 정답 정책이 A·B 모두
  67% 로 같았지만, 30% 정답 정책은 A 0% · B 33% 로 갈렸다. 조작 정책이 `Math.random()` 이라
  측정할 때마다 흔들리는 폭이고 판정 구간 안이지만, 실제 참가자 자료를 볼 때 ver 을
  공변량으로 넣을지 정해야 한다.
- **`mode=tutorial` 은 이제 러너가 띄우지 않는다.** 조작 연습은 광고 밖(저장소 루트
  `practice.js`)으로 옮겼다 — 이유는 `INTEGRATION.md` §5-5. 여기 남은 튜토리얼은 게임을
  단독으로 열어 볼 때와 `npm test` 점검용이다. 충돌해도 그냥 넘어가는 동작(`tutorial_fail`)도
  그대로 두었다. 실험에서 조작을 익히는 것은 `practice.js` 몫이고, 그쪽은 해내야 넘어간다.
