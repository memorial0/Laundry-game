# game — 마이크로게이트 실패-수정형 게임 광고 자극

`memorial0/game_setup`(내부 이름 `micro-rescue-experiment`)을 이 저장소로 흡수한 것이다.
가져온 시점의 원본 커밋: `11e85a98ae157d7dd52fb1687f0d25cbd3715669` ("package-lock.json 갱신").
이후 변경은 전부 이 저장소에서 관리하며, 원본 저장소로 되돌려 보내지 않는다.

## 실행

```bash
npm install
npm run dev        # vite dev 서버 (기본 4173, 점유 시 자동 증가)
npm run build      # dist/ 로 정적 빌드 — 통합 러너가 iframe으로 읽는 산출물
npm test           # 세 조건을 jsdom 에서 끝까지 재생해 단계·로그·길이 확인 (약 1분 40초)
npm run difficulty # 개입 구간 성공률을 조작 정책별로 측정 (약 1분)
```

## 길이·난이도를 고치는 자리

- 길이: `RESCUE_SEC`·`TUTORIAL_SEC`·`REWIND_SEC` 상수와 `MAIN_TIMELINE_A` 의 `t`(초).
  고친 뒤 `npm test` 로 실측한다. 목표는 세탁 자극과 같은 watch 31초 / intervene 55초.
- 난이도: 게이트의 이득/손해 값과 적 HP. 고친 뒤 `npm run difficulty` 로 확인한다.
  **손해 상자는 반드시 음수여야 한다** — 둘 다 양수면 아무 데나 지나도 파워가 올라
  "개입이 결과를 바꾼다"는 조작 자체가 성립하지 않는다(실제로 그랬고, 무조작 성공률이 100%였다).
- 되감기 지점(`REWIND_SEC`)은 자동 조종의 첫 오판보다 **앞**이어야 한다. 이미 손해를 본
  지점에서 시작하면 참가자가 만회할 수 없어 성공률이 0%가 된다.

## 걷어낸 것 (통합 러너가 대신한다)

이 자극은 원래 **독립 실험 러너**였다. 통합 러너(`session.html`)가 참가자 ID·순서 배정·설문·
로그 내보내기를 전부 담당하므로 아래를 제거했다.

- 참가자 ID 입력 화면 / 공통 안내 / 세션 인트로 / 최종 비교 설문 / 완료 화면
- 세션별 설문 5문항 — 통합 설문(`survey.js`)으로 대체
- CSV/JSON 내보내기 버튼
- 2세션 루프(`CONDITION_ORDER`) — 이제 한 번에 조건 하나만 재생한다
- 효과음 전체(Web Audio) — 세탁 광고가 무음이라 자극 간 비교에 얹히던 변량이었다
- 시작 버튼 — 소리가 없어져 필요 없다. 세탁 광고처럼 로드 즉시 재생한다

남은 것: 게임 자극 자체(캔버스·타임라인·되감기·개입), 조건 파라미터, 종료 시 로그 postMessage.

## 파일

- `src/stimulus.js` — URL 파라미터 파싱, 로그 스키마, 종료 통지. 게임 로직은 없다
- `src/MicrogateExperiment.jsx` — 자극 본체
- 규격 전체는 저장소 루트 `INTEGRATION.md`

## 알려진 미해결 사항

- **평행 자극(ver B)이 없다.** `MAIN_TIMELINE` 하나뿐이다. 같은 참가자가 시청·개입을 모두 겪는
  참가자내 설계이므로 게이트/적 수·난이도·길이를 맞춘 두 번째 타임라인이 필요하다.
  그때까지 `ver=B` 요청은 A 로 재생되고 로그에 `VER_FALLBACK: 1` 이 남는다.
- **튜토리얼에서 충돌해도 그냥 넘어간다**(`tutorial_fail`). 원본 동작을 그대로 뒀다.
  조작을 못 익힌 참가자가 개입 조건에 들어가는 셈이므로, 재시도를 붙일지 정해야 한다.
